## [Unreleased] - ReleaseDate

### Added

- Scenes with hotspots and walks for stage hosts (P6-02, #96). A variant of a room's `illustration` has `regions`: `{ thing: iron_gate, rect: [31, 33, 38, 67] }` or `{ exit: north, rect: [..] }`, in percent of the image. `Session::media()` has the field `regions` with the hotspots the player can see now, each with its name. `Session::set_host_walks(true)` (WASM `setHostWalks`) makes a command on a thing in the room, or a move, first wait for `walk_to` with that `thing` or `exit`; `arrived` runs the command and `refused` drops it. Without it, nothing changes. `loremaster check` reports regions that point to nothing. The web player shows the hotspots as buttons over the illustration, and the gatehouse example has them.
- **Breaking (library):** `AwaitRequest::WalkTo` has the new fields `thing` and `exit` (match it with `WalkTo { room, .. }`), `Awaiting` has the new field `command`, and `MediaVariant` has the new field `regions`. `Command` now derives `Hash`.
- Editor overrides of Rust parts (DSL step L6, DS-11 to DS-15, #99). Each entity from Rust has a content hash of its model value in its `Origin::Rust`. A YAML file with an `override:` block replaces a Rust part and keeps its base (file, line, entity, hash, commit, and the value for the diff). `assemble` compares: Rust unchanged is a warning, Rust changed is an error with a three-way diff, Rust equal to the override is an info. `loremaster codegen <dir>` prints overrides as `world!` snippets, `loremaster export-pack` writes Rust packs to `packs/*.yaml` for the generic editor (`Pack::to_yaml`; it writes them atomically and removes stale ones; only the top level of `packs/` is read, any other file there is an error, and a leftover `packs/*.json` says to export again). Two dialogues or two verbs with one id are an error, as for the other kinds, and `world_test!` with `Loremaster::assert_world` and `strict` is the whole-world test. The editor shows Rust parts read-only with their source line in Atlas › Rust and can eject or override them. `examples/rust-overrides` is the reference example.
- **Breaking (library):** `Origin::Rust` has the new field `hash`, `Severity` has the new variant `Info`, `Pack` has the new fields `overrides` and `commit`, and `Project` has the new field `rust_parts`.
- The host contract (P6-03, #97). `interface:` in story.yaml (or `interface { .. }` in `world!`) declares every custom action (name, typed arguments, results) and every host event (name, typed arguments, optional precondition). With the section, `loremaster check` fails on an undeclared action or event, a wrong argument type and a missing branch for a declared result. `Session::host_event` reports an event, `Session::for_host` and `Session::check_interface` refuse a host built for another interface hash, and name the added, removed and changed entries. A walkthrough reports an event with `{ event: killed, args: { .. } }` and gives only declared results. The new crate `loremaster-build` (for `build.rs`) and `world!` generate the Rust types; `loremaster interface <dir> [--rust|--ts|--json-schema]` writes them for other hosts. The names of the interface are plain names, and the check reports two that make one Rust name. Stories without the section work as before.
- Protocol mode (US-65): `loremaster protocol <dir>` plays a story as a JSON-RPC server on stdio, one message per line, with the Session API as methods. It lives next to the MCP server in `loremaster-mcp` and leaves the MCP tools alone.
- **Breaking (library):** `Story` and `StoryHeader` have the new field `interface`, and `StepPlan` has the new fields `event` and `args`; code that builds them with a struct literal needs them.
- Media and audio slots with captions (P6-01, #95). A room, thing or machine state has `media:` (illustration, portrait, music, ambience) with variants by condition. Assets are in `assets/` with `file`, `caption`, `licence`. `play_sound` is a one-shot rule effect, and a walkthrough checks it with `sound:`. `Session::media()` derives the slots from the state, so they are not saved. `loremaster check` reports missing and unused assets, missing files, licences and captions. The web player shows images, plays audio after the first input, and has captions, three volumes and a mute key (Alt+M); the sound is off by default. The new example `gatehouse` is the fixture.
- **Breaking (library):** `Room`, `Thing`, `StateDef::Described`, `Story`, `Pack` and `Expect` have new fields, `Effect` (model) has the new variant `PlaySound`, and `Turn` has the new field `sounds`. `session::Effect` has the new variant `Sound` (it is `non_exhaustive`).
- Episodes (TX-12, US-13, dramaturge#81): `export:` and `import:` in story.yaml list the facts, relations (`thing.axis`) and memories (`thing.key`) that one story of a series hands to the next. `loremaster check` examines both lists. `Session::episode()` writes an `Episode` (format `loremaster-episode`, version 1, the story id), and `Session::from_episode` starts a new game of the next story with what it imports; the `Imported` report lists what it took, what the story does not import and what does not fit. An imported memory declares its key for `remembers()`.
- **Breaking (library):** `Story` and `StoryHeader` have the new fields `export` and `import`.
- Several player actors (P6-06, #100; WO-5, WO-14, TX-9): `playable: [wick, bilge]` in story.yaml gives the player a list of actors. `switch to bilge` makes one the active actor, whose room, carried things and senses are the player's; `seen_by(actor)` now tests the active actor. `bilge, take spanner then s` gives another actor an order: one step per turn, with a report at the end. The two-robot demo in `examples/two-robots` shows it: a puzzle that needs both robots, text per perceiver, and an explorer that ends.
- **Breaking (library):** `Story` and `StoryHeader` have the new field `playable`, `State` has the new fields `active` and `orders`, and `Input` now derives `Eq`. A `Command` with an `actor` that is a playable actor is now an order; for any other thing it is still refused.

- A terminal example host (P6-04, #98) in `examples/terminal-host`: it plays a story through the Session API only, with every effect, status and await, and with a save file. Its README says what a host must do. A test plays the Lighthouse walkthrough over piped input.
- The stat sheet, the dice display and the combat panel of the web player (P5-04, #91). `stats:` in story.yaml declares the sheet: `{ var, label, short, max }` for a number or a codeword. `Session::stats()` and `Session::combat()` are in the WASM binding. `Effect::Roll` and `Turn::rolls` give the dice of a turn, with the faces, the target and the result of a Luck test in a combat. `against: <var>` on a roll names its target for the display. The dice are ASCII art with a short roll animation in the phosphor theme and drawn dice in the other themes; with reduced motion the result shows at once.
- **Breaking (library):** `Story` and `StoryHeader` have the new field `stats`, `AwaitSpec` has the new field `against`, `Turn` has the new field `rolls`, and `Effect` (of the session) has the variant `Roll`.
- A `check` rule that waits for the host now holds the action. Before, the move or the verb ran while the rule waited.
- The Salt Tower (P5-06, #93) in `examples/salt-tower`: a gamebook of 9 sections as rooms, with labelled exits, stats with limits, Skill and Luck tests as machines, the built-in combat and a codeword. Its walkthroughs (pay, fight, grate, spent) and the reachability of all sections run as a test.
- Combat (P5-03, #90): the effect `combat: { enemies: [warden], win: yard, loss: fallen, escape: road, together: false }` runs a fight by built-in rules, also in the web player and `loremaster test`, without Rust. Enemies are things with the number properties `skill` and `stamina`. Each round is a choice ("Attack", "Test your Luck" after a hit, "Escape" when allowed); the rolls are visible roll notices and a walkthrough can force them with `rolls:`. A save in the middle of a combat restores. `Session::combat()` gives the enemies, the attack strengths of the last round and a short log. The explorer sees win, loss and escape.
- The id of an await is now unique for each await, also in a loop, so that a repeated answer can not answer the next one.
- **Breaking (library):** `Effect` has the new variant `Combat`, and `State` has the new fields `await_seq` and `combat`.
- Machine loops (P5-02, #89): a machine step with `on: next` runs by itself right after the machine enters its `from` state, in the same turn, and when the game starts in that state. Such steps chain and loop. An `await` in one suspends the chain as data in the save, and the chain goes on after the answer. `step_limit: <n>` in story.yaml (default 100) caps them per turn, counted anew after each answer to an `await`: the chain stops with a note and a `limit` log entry. The checks reject a loop that can never stop, and `on: next` outside a machine. `on::next()` in the builder and `on next` in `world!`.
- `world!`: Rust behaviors (DSL step L5, #92). `behavior Thief::zork();` names a behavior and registers its instance, `#[behavior(on = turn)]` makes a behavior of a function, and `rust |cx| { .. }` is Rust code at its place in a rule or a machine step (the behavior `<rule>#rust`). The builder gets `register`; `examples/parrot-cove` shows all three. The rules view shows a `rust` block as `run Rust (..)`.
- **Breaking (library):** `loremaster_project::Pack` has the new field `instances`; code that builds it with a struct literal needs it.
- Machine loops (P5-02, #89): a machine step with `on: next` runs by itself right after the machine enters its `from` state, in the same turn, and when the game starts in that state. Such steps chain and loop. An `await` in one suspends the chain as data in the save, and the chain goes on after the answer. `step_limit: <n>` in story.yaml (default 100) caps them per turn, counted anew after each answer to an `await`: the chain stops with a note and a `limit` log entry. The checks reject a loop that steps can reach and that can never stop, and `on: next` outside a machine. `on::next()` in the builder and `on next` in `world!`.
- **Breaking (library):** `EventPattern` has the new variant `Next`, and `Story` and `StoryHeader` have the new field `step_limit`. `Turn` has crate-private fields now, so code outside the crate can not build one with a struct literal.
- Dice in tests and numeric stats (P5-01, #88). A walkthrough can set its own `seed:`, and a step can force the totals of its rolls with `rolls: [4, 11]`; a total out of the range of the dice or a total that no roll takes fails the test. A number variable can have `min` and `max`, a number or the id of another number variable; the engine clamps each write to it, and `loremaster check` rejects limits on another type, an unknown variable and a constant `min` above `max`. The new effect `calc: { total: "r + skill - 1" }` sets a number from a sum of numbers and number variables or properties. A save keeps the RNG, so after a load the next roll is the same. The builder has `var_min`, `var_max`, `calc`, `seed` and `rolls`; `world!` has `var x = 1 min 0 max y;`, `calc x = a + b;`, `seed 42;` in a test and `rolls 4, 11` on a step.
- **Breaking (library):** `VarDef` has the new fields `min` and `max`, `Walkthrough` has `seed`, `WalkStep::Checked` has `rolls`, and `Effect` has the variant `Calc`; code that builds them with a struct literal or matches `Effect` exhaustively needs them.
- `loremaster play` shows the things the text mentions (people too) in cyan, when the output is a terminal. Line wrapping no longer counts color codes as width.
- Docs: the second dramaturge fit report (P4-09, #86), `docs/dramaturge-lock-keeper-fit.md`: what dramaturge 0.3.0-alpha.5 does for loremaster on the Lock-Keeper, the glue in lines against phase 3, the friction found, and ranked requests for dramaturge 0.3.0.
- The Lock-Keeper demo (P4-07, #84) in `examples/lock-keeper-slice/demo`: the design "The Lock-Keeper's Night", steps 1 to 7, in YAML. Nine rooms, four suspects with agendas, the windlass concealed in the tool chest, the lock machine with its drain timer, the case notebook as three quests, the accusation and five ranked endings. The walkthroughs `best`, `ashes` and `wrong_man` pass, give the hint ladder and the step chart, and their transcripts are in `expected/`; the ending checks over the whole night find no dead end and accept each point of no return through a `closes`. `examples/lock-keeper-slice/README.md` says how to play it. `expected/slice_best.transcript` holds the transcript of the slice's best path.
- Talks play a node's `lines` and `next` (dramaturge R2, #155): the lines show in order after `say`, each by its `speaker` (a line of the player shows like an answer), and a node without an answer to choose goes on to its `next` node in the same turn, with the outcomes of each node. A loop of `next` without a choice is a check error, and in the game it stops after 1024 nodes and ends the talk. `loremaster check` no longer reports `lines` and `next`; the Atlas dialogue outline shows them. In `world!`, a node's body takes more lines (`<speaker>: "…";`, a thing or `player`) and `-> <node>` / `-> end` / `-> back` as `next`; the builder has `DialogueBuilder::line` and `next`.
- Ending checks (CK, P4-04, #81): the state explorer keeps the explored graph and walks back from the endings. A dead end (a state from which no ending can be reached) is an error, with the shortest command list, the room and the rule of the last turn. A point of no return (a turn after which the best reachable ending by `rank` gets worse) is a warning, unless a rule or machine step names the lost endings in `closes: [<ending ids>]` with a `reason`; the check compares the list with the endings that really drop out, and warns about a `closes` that names an ending which never drops out. When the budget stopped the walk, the checks say "not proven" and report only what they proved. `Exploration::ending_checks` (`EndingCheck`, `DeadEnd`, `NoReturn`, `StaleCloses`) holds the findings and `EndingCheck::diagnostics` gives them as diagnostics; `loremaster explore`, the Workbench, the AI tool `explore` and Atlas › Checks › "Whole game" show them. `loremaster check` rejects an unknown ending in `closes` and `closes` without a `reason`. This replaces the earlier `allow_unwinnable` idea.
- **Breaking (library):** `loremaster_model::Rule` and `loremaster_model::Step` have the new fields `closes` and `reason`; code that builds them with a struct literal needs them. The builder API has `RuleBuilder::closes` and `MachineBuilder::closes`.
- Quests (decision D8): a machine with `quest: true` and `title`; its states give the journal with `journal:` text and `done: true`. `Session::journal()` (and `journal()` in the web engine) lists the quests whose state has journal text, open ones first, without a step; the player types `journal`. Steps and `set` move a quest. The builder gets `quest` and `journal`.
- Action phases: `check` rules run before a verb, and the new `stop` effect refuses the action.
- Rules in thing and room files, `within:` for a thing, room or region, and `priority`. More specific rules run first.
- Timers (`timers/`, or `timers:` in story.yaml), `timer.<id>` in conditions, and the effects `start` and `cancel`.
- `chance(n)` in conditions, with the same result for the same state.
- Custom events (`emit`, `on: { event }`) and dialogue events (`on: { talk: [dialogue, node] }`).
- Containers and supporters (`location: { in: box }`, `{ on: table }`), the `put` verb, `capacity`, and `in(thing, holder)` in conditions.
- Scenery in more rooms or regions with `also_in`.
- The score (`score:` in story.yaml) and the `score` command.
- Puzzle machines (`machines/`) with named states and steps, and Atlas › Machines in the editor.
- Walkthrough tests (`tests/*.yaml`) and `loremaster test`.
- Hints and the dependency chart from walkthroughs (P4-05, #82): a step can have `id`, `at`, `needs`, `before` and up to three `hints`. `Session::hints`, `Session::hint` and the typed word `hint` give the hint ladder of the current room, one level at a time; the editor shows it in the Here panel. `Workbench::charts` and Atlas › Steps draw the chart from `needs`, with the puzzle width. `loremaster check` warns about a hint that names a later step and about long runs of steps in series only. `loremaster quality` lists one-way exits, rooms with the same text, things that nothing uses (unless `red_herring: true`), the puzzle width and the verbs that no walkthrough uses.
- **Breaking (library):** `WalkStep::Checked` has the new field `plan`; code that destructures it needs `..`. `Thing` has the new field `red_herring`.
- `model_hash(story)`: the canonical hash of a model (SHA-256 of the story as JSON). The golden slice keeps the hash of its YAML form in `expected/model.hash`.
- Behavior manifests (XP-4): `Behavior::manifest` names the facts a behavior reads and writes and the event kinds (`EventKind`) it handles. The game sends it only those events, logs a note for a write the manifest does not name, and the rules view and the explorer use it. Without one, a behavior is opaque, as before.
- The `call` effect: `call: thief` runs a behavior at its place in a rule, with `Event::Call(owner)` (the rule's id, or `dialogue:<id>` / `timer:<id>`); `Flow::Stop` stops the rest of the rule, the dialogue node's effects or the timer step's effects. In a dialogue's `then`, as in a rule, `stop` and `end` end the effects that follow. A `call` that names no behavior of the story is a check error; at run time, a behavior that the story does not name or that the build does not have is a note in the log.
- The Session API (ADR 0003): `Session::new`, `with_seed`, `load`, `from_save`, `start`, `submit(Input)` (text, command record, choice, tick), `choose`, `save`. Each call returns a `Step`: effects as data (`Text`, `Notice`, `Choices`, `Ending`) and a `Status` (ready or ended). A tick lets time pass without an action, also during a talk (`Game::tick`). Notices are only changes of state (`set`, `move`, `timer`, `talk`, `memory`, `relation`).
- **Breaking (library):** `loremaster_model::Effect` has the new variants `Await` and `Call`, and `loremaster_runtime::Event` the new variant `Call`; code that matches them exhaustively needs arms for them.
- The `await` effect: a rule stops until the host answers a choice, a roll, a walk or an action, and goes on with the answer (`Session::resume`, `Status::Await`). A save game keeps the waiting rule, and the explorer tries each answer.
- Undo, snapshots and the death prompt (SE-8, SE-9): `Session::undo` (also the text `undo`), `set_undo_depth`, `snapshot`, `restore` and `restart`. An ending of kind `death` sends a death prompt await (`undo`, `restart`, `restore`), unless story.yaml says `death_prompt: false`. Walkthroughs run through the Session API.
- Speech segments (P3-15, #111): a `say` of a rule, a dialogue node, an option or a machine step is a line, a text or a list of segments: bare strings and `{ narrate: … }` are narration, `{ says: …, by: <thing or player> }` is speech, and the renderer adds straight double quotes. A segment with `when` shows only while its condition holds. `line:` is an alias of `say:`. The speech of a node is the dialogue's thing's, the speech of an option the player's. Output runs of speech carry their `speaker`. `loremaster check` examines each segment and its `by`, and warns about a bare string right after `says`. A line that is one text is written out as before, so model hashes do not change.
- **Breaking (library):** `Effect::Say`, `DialogueNode::say`, `DialogueOption::say` and `Step::say` hold a `loremaster_model::Line` instead of a `String` (`Line::plain`, `From<&str>`, `Line::as_plain`, `Line::source`); `CompiledDialogue::node_say` and `option_say` hold a `loremaster_lang::CompiledLine`, and `Run` has the new field `speaker`.
- `extend: true` and `replace: true` in an entity file of a later pack: `replace` takes the place of the earlier entity (with a warning), `extend` adds lists and map entries to it; a value that both packs set is an error.
- The schema checks as one library function (XP-5): `loremaster_project::check_packs(packs)` joins packs and checks ids, references, facts, conditions, markup and reserved names, with no files and no I/O, so that the `world!` macro can run it at compile time. `check_files(files)` runs it for a YAML folder; the CLI, the web engine and the AI tools use it. Both return `Checked { project, diagnostics }`. Diagnostics about the story header name the file of its origin instead of always `story.yaml`.
- The builder API (DSL step L2, DS-3): the new crate `loremaster-dsl` writes a story in plain Rust as a `Pack` (story header, rooms, exits, things, fragments, rules with events and effects, machines, timers, endings, verbs, dialogues, threads, walkthroughs). Each entity gets an `Origin::Rust` with the file, line and column of the call. `Loremaster::new().pack(..).yaml(..).build()` joins packs from Rust and YAML in order, checks them and compiles the world. A test proves that the Lighthouse from the builder equals the Lighthouse from YAML, value by value and by `model_hash`. The crate `loremaster` gives the API as `loremaster::dsl` and `loremaster::prelude` with the new cargo feature `builder`.
- The `world!` macro (DSL step L3, DS-4, D7): the new proc-macro crate `loremaster-macros`. A block with a story header, vars, rooms, things, rules (events, conditions as tokens or strings, effects), machines, timers, endings, verbs and walkthrough tests makes `pub fn pack() -> Pack` through the builder API; each entity gets an `Origin::Rust` at its id in the block. At compile time the macro runs `check_packs` on the pack, with stubs for the ids in `extern { .. }`, and reports unknown ids, reserved names, bad conditions and bad markup as compile errors at their tokens. Dialogues, text pools, `one_of` and agendas are not in the grammar yet; the macro names the step or issue for each. The cargo feature `dsl` of the crate `loremaster` now gives `loremaster::dsl`, `world!` and `loremaster::prelude`; `builder` is its old name. The `world!` forms of the golden slice compile for the parts in today's syntax, and `slice_equivalence` passes: YAML, DSL and mixed give one model hash.
- Dialogues and more in `world!` (DSL step L4, P4-08 #85): `dialogue [<id>] with <thing> start [..] { .. }` in dramaturge's token form (`dramaturge_syntax::tokens::parse_dialogue`), with the conditions, speech segments and effects (`then <effect>`) of `world!`; dramaturge's and loremaster's checks of a dialogue are compile errors at their tokens, and the model equals the YAML one. Also `thread`, `behavior`, frames (`before`, `instead`, `after`), name stages (`name`), `relations`, `score`, `score_var` and `ranks` in the story header, a fragment's `id`, `replaces` and `note`, `replace` before an entity, `extern { thing stove [hot: bool]; relation trust; }`, and `pack <name>;` for the name of the function. The builder has `DialogueBuilder::speaker`, `option_id` and `then_effects`, and `Effects` for `Vec<Effect>`. The keeper dialogue of the golden slice compiles in `world!` with an inline line in place of its text pool and equals `dialogues/keeper.yaml`; the pool (R9) keeps `dsl/dialogue.rs` out of the build.
- Speech segments in `world!` (P3-15, #111): `line "The lock-keeper shrugs." keeper says "Prove it," narrate "he says.";`, a bare `says` without a speaker, and `when <cond> then <segment>` for a segment that shows only while the condition holds. They give the same `Line` values as YAML. A bare string right after `says` is a compile error that suggests `narrate`. The golden slice uses segments in all three forms (`rules/accuse.yaml`, `machines/lock.yaml`, `dsl/today.rs`, `mixed/machines/lock.rs`), with a new `expected/model.hash`.
- The Workbench API (SE-13, SE-14, ADR 0003): the new crate `loremaster-workbench`. A `Workbench` owns a `Session` (`session()`, `session_mut()`) and gives the authoring views: `atlas`, `map`, `rules`, `machines`, `symbols`, `try_markup`, `try_markup_in`, `try_condition`, `describe`, `preview_situation`, `assembly`, `room_parts`, `last_frame`, `talk_view`, `inspect_thing`, `inspect_exit`, `vars`, `phases`, `room_matrix`, `text_matrix` and `explore`. `author` runs an author command, and `start` and `play` give whole turns with the rule log for an editor transcript. `reload(world)` carries the running game over to a changed world: the room, the values and the things stay, and what the new world does not have is dropped. The undo history does not carry over. The web engine, the AI tools and the terminal use it.
- Read-only queries on `Session` (ADR 0003, point 8): `scene`, `verbs`, `preview`, `talk` and `choices`.
- Actors and agendas (D6, WO-5, WO-6, P4-02 #79): `agendas/<id>.yaml` gives a thing an agenda, a list of steps with `at` (a time of day), `place` (a room), `when`, `do` (a command of the actor), `then` (effects), and `closes` with a `reason` (the endings that the step closes on purpose, for the ending checks). A due step walks its actor to the place along the exits, one room per turn, then runs; a timed step whose `when` does not hold is skipped, a step without `at` waits for its `when`. An open talk with the actor holds the step back, and it runs late after the talk. The player sees an actor come and go. `loremaster check` checks the actor, the places, the conditions, the commands, the effects and the endings of `closes`. The explorer waits in a story with agendas, as for timers, and tells states apart by the minutes until each agenda's next step. The ending checks read an agenda step's `closes` as a rule's, and name it `agenda:<id>/steps[<i>]`. `Story::agendas`, `agenda`, `agenda_of` and `actors`; `loremaster_model::{Agenda, AgendaStep}`.
- Action cost, concealed things and the carry limit (WO-2, WO-3, WO-4, P4-03 #80): `clock: { costs: { search: 10 } }` gives a verb its own minutes per turn of the player, for standard and custom verbs; an unknown verb there is a check error. A thing with `props: { concealed: true }` is out of the room text, the contents, the inventory and the parser's scope until the new standard verb `search` (`look under`, `look behind`, `look in`) finds it in or on its object, or a rule sets `concealed` to false. `carry_limit: <n>` in story.yaml caps the things in the player's hands; `take` beyond it says "Your hands are full." The explorer searches where a thing is concealed and, with a carry limit, drops things to free a hand. `ClockConfig::costs` and `minutes_for`, `Story::carry_limit`, `State::is_concealed` and `held_count` (which leaves out concealed things in the hands).
- **Breaking (library):** `ClockConfig` and `Story` have the new fields `costs` and `carry_limit`; code that builds them with a struct literal needs them (or `..Default::default()` for the clock).
- **Breaking:** `search` is a standard verb now. A custom verb with the id `search` runs the built-in search instead of its `default` text.
- The Command record (D6, SE-2): a command has an actor, a verb, a direct and an indirect object, a preposition and a topic. A rule's `verb` or `check` event can name the slots, `on: { verb: examine, direct: stove, actor: keeper }`; the list form `verb: [examine, stove]` stays and gives the same model. An event without `actor` matches only the player's commands. The parser fills `preposition`. `loremaster_model::CommandPattern`, `loremaster_runtime::{CommandRecord, PLAYER}`, `Command::verb`, `Command::record` and `Event::command`.
- **Breaking (library):** `EventPattern::Verb` and `EventPattern::Check` hold a `CommandPattern` instead of a `Vec<Id>` (`CommandPattern::from_parts`, `parts`, `objects`); `EventPattern` has a hand-written serde form. `Command::Verb` and `Event::Verb` have the new fields `actor`, `preposition` and `topic`: build a command with `Command::verb(verb, objects)`, and match with `..`. In JSON, the new fields of `Command::Verb` are optional, so hosts send the same commands as before.
- **Breaking:** save version 2 (ADR 0001): the state has `actors`, the progress of each actor's agenda. A save of version 1 (or 0) migrates: each agenda starts at its first step. A restore into a changed story drops the steps that the story no longer has, as `agenda:<actor>#<step>`.
- `Pack` and `assemble` in `loremaster-project` (DSL step L1): each source makes a pack, and `assemble` joins packs in their order. An id that two packs define, or a second story header, is an error that names both origins. `load` is one YAML pack, assembled.
- Save games are an envelope with a format version, the story id, a hash of the story and the state. A restore migrates older saves (also the bare state of 0.1), refuses a newer version or another story with a message, and keeps the valid state of a changed story with a list of what it dropped. Read `docs/adr/0001-save-compatibility.md`.
- Endings as entities (`endings/`): a kind (`win`, `loss`, `death`, `neutral`), a rank, a title and a text. The save game keeps the ending, `expect: { ending: … }` checks it in a walkthrough, and `loremaster check` reports unknown and unused endings.
- Pending tests: `pending: { phase, needs }` in a walkthrough, `#[ignore = "pending: ..."]` in Rust, `task test:pending`, and a CI job that fails when a pending test passes.
- The golden slice `examples/lock-keeper-slice`: a part of the Lock-Keeper demo in YAML, with `slice_baseline` and eleven pending tests for the roadmap phases 1 to 4. Read its `PENDING.md`.
- The draft `world!` forms of the golden slice (`dsl/`, `mixed/`), behind the new cargo feature `dsl` of the crate `loremaster`. They do not compile until DSL step L2.
- Behaviors in Rust: the `Behavior` trait, `World::register`, and `behaviors:` in story.yaml or `behaviors/`.
- `verbs/` for custom verbs in their own files.
- Zork I: containers, scenery, the score and value of treasures from the importer; the lamp battery, the trophy case, the exorcism, the dam and the thief ported by hand. Read `docs/zork-fit-test.md`.
- Text pools on dramaturge's text selection core (P4-01, #78; R9 of dramaturge 0.3): a fragment with `one_of` is a group that shows the candidates its `pick` chooses (`first`, the default; `best`, the candidate with the most tests; `all`), and `texts/<id>.yaml` holds a named pool that a rule or a dialogue node shows with `say: { text: <id> }`. A candidate has `key`, `when`, `mode`, `text` or `variants`, `learn`, `speaker` and `topic`. `learn: [var]` sets story variables to true when the text shows in play, and `seen_by(x)` in a condition is true when `x` sees the text (the player, until actors come). Descriptions, presence texts, frames, the intro, rules and dialogue lines all go through the core; previews and the Atlas choose without a change to the game. `first_time` is an alias of `first_visit`. `loremaster check` reports dramaturge's pool checks at the file of the pool: a tie of two `best` candidates (warning), a candidate with progress and no key (warning) and an unknown pool (error), and checks `learn`, `speaker` and the pool of `say: { text: … }`.
- **Breaking (library):** `loremaster_model::Fragment` has the new fields `learn`, `pick` and `one_of`, `Line` the new field `pool`, `Story` the new field `texts`, and `Pack` the new field `texts`.

### Changed

- loremaster depends on dramaturge 0.3.0-alpha.5 from crates.io (the text selection core, R9).
- **Breaking:** save version 3 (ADR 0001). Text progress uses dramaturge's keys: `room:shore/2` instead of `room:shore#2`, and the fragment's `id` in place of its index when it has one. The save field `sticky` of a fragment's progress is `pick` now (`sticky` still loads), and the step from version 2 renames old keys; a fragment with an `id` starts its progress over. `shuffle` never shows the variant it showed last; `first_visit` on an examined thing, the intro and a frame means the first time the text shows, and on a presence text the first visit of the room, as on a room. The explorer finds 4 instead of 3 texts of the Lighthouse shore (its `shuffle` fragment); no walkthrough or test transcript changed.
- The explorer counts a walk that the depth limit (40 commands) stopped as `truncated`, as one that the state budget stopped. `stuck` counts only proven dead ends: a state whose future the walk did not finish is not one.
- Dialogues use more of dramaturge 0.3: `add` lowers to `Outcome::AddFact` (a missing value counts as 0 as before; the sum now saturates at the `i64` limits instead of overflowing), `remembers()` queries the memory id (memories no longer carry the key as a tag), the checker filters validator issues by kind and skips cycles through the validator options, and the player's key comes from `SymbolTable::PLAYER_KEY`. Saves stay compatible.
- **Breaking (library):** `loremaster_lang::ADD_KEY` and `loremaster_lang::memory_tag` are removed.
- Dialogues run through more of dramaturge 0.3.0-alpha.3: the start nodes are the entry nodes of the graph, and a talk starts at the first one whose `when` holds through dramaturge's `select_entry`. The checker no longer needs to drop the "unreachable" warnings of start nodes. A `then` list is a typed host outcome (`Outcome::Host`) in the graph, not a custom outcome with an index into a side list, and each line is typed host text (`DialogText::Host`) with its compiled markup, not a side table. A node is entered through dramaturge's `enter_node`, and `go` and `go: back` move a dramaturge `DialogCursor`. Saves keep the talk as node keys, as before.
- A `go` to a node whose `when` does not hold ends the talk. Before, the talk entered the node anyway. A `when` on a node that is not a start node was not documented. `go: back` returns to the node before without a check, as before: that node was entered already, and its outcomes do not apply again.
- **Breaking (library):** `CompiledDialogue` is now the lowered graph itself, a `DialogueGraph<Vec<Effect>, CompiledLine>`. Its fields `starts`, `effects`, `node_say` and `option_say` and `loremaster_lang::THEN_KEY` are removed; use `entry_nodes`, `Outcome::Host` and `DialogText::Host`.
- **Breaking:** a variable, machine, room or thing whose id is a built-in name of conditions (`here`, `turns`, `level`, `first_visit`, `time`, `action`, `timer`, `true`, `false`, `and`, `or`, `not`, the functions `in`, `carried`, `present`, `visited`, `visits`, `chance`, `remembers`, and the planned `seen_by`) is a check error at its declaration, and so is a variable or machine with the name of a clock phase. Before, it loaded, and its conditions silently read the built-in, or the variable instead of the phase. `loremaster_lang::RESERVED_NAMES` is the one list, and `loremaster_lang::reserved` tells a keyword, a derived value and a function apart for the message; the ZIL importer uses it too and adds `_zil` to such names and to the phase names of the default clock.
- **Breaking:** the loader rejects an unknown field in every entity file (rooms, things, rules, dialogues with their nodes and options, timers, verbs, machines, story.yaml and walkthrough steps and `expect`), an unknown folder and a YAML file other than story.yaml at the top, with the nearest known name: ``unknown field `descripton`: did you mean `description`?``. Before, only endings, threads and story.yaml rejected unknown fields, and an unknown folder loaded as nothing. A fragment with an unknown field names the field instead of "did not match any variant". The folders `agendas/` and `texts/` of the golden slice are skipped with a warning. `loremaster_project::FOLDERS` lists the folders, and `Pack::warnings` holds the warnings of a pack.
- **Breaking (library):** `Cx` is a narrow, stable view for behaviors (XP-1, XP-7). `Cx::state()` and `Cx::world()` are gone; use the new `turns`, `minutes`, `visited` and `room_has_tag`, or the read-only escape hatch `Cx::unstable()`. Random numbers come only from `Cx::roll`.
- loremaster depends on dramaturge 0.3.0-alpha.3 from crates.io, with an exact version, instead of the git branch `feature/0.3`. CI builds with `--locked`, packages the crates on every branch again, and a job that is not required tests against the newest dramaturge on `feature/0.3`.
- **Breaking:** the loader reads `agendas/` (D6) instead of skipping it with a warning. `texts/` loads since P4-01 (#78), so no folder is skipped any more.
- The turn log of a talk shows what a dialogue really changed, in the order of the changes, with the new values. Removed facts and forgotten memories get a line; a relation change of 0 and a fact outside the world scope do not.
- The room matrix and the text matrix try the player's relations to things (`blackbeard.trust`) as a dimension.
- One diagnostic form (XP-6): `Diagnostic` and `Severity` live in `loremaster-model` (`loremaster-project` re-exports them) and can be deserialized. A compile error becomes a `Diagnostic` with `Diagnostic::from(&error)`, and `Project::locate` gives it the file of its entity. The CLI, the web engine and the AI tools report compile errors with their file now.
- **Breaking (library):** `Project::origins` maps to the `Origin` enum (`Yaml { path }`, `Rust { file, line, column, pack }`, non-exhaustive) instead of a path string. `Origin::file()` gives the path.
- `Game::save` and `Game::load_save` read and write save games. The web engine's `save()` and `restore()` and the AI tools `save` and `session_start` use the envelope; `restore()` returns the dropped ids.
- **Breaking:** the `end` effect names an ending from `endings/` (`end: beacon_lit`) instead of a text. Move the text into `endings/<id>.yaml` with a `kind` and a `title`. The lighthouse and the tower examples show it.
- **Breaking (library):** the authoring views moved out of `Game` into `loremaster-workbench`. `Game::atlas`, `map`, `rules`, `machines`, `symbols`, `try_markup`, `try_condition`, `try_markup_situation` (now `Workbench::try_markup_in`), `preview_situation`, `describe_preview` (now `Workbench::describe`), `assembly`, `room_parts`, `last_frame`, `talk_view`, `inspect_thing`, `inspect_exit`, `vars`, `phases`, `author` and `carry_over` (now `Workbench::reload`) are gone from the public API, and so are the free functions `explore`, `room_matrix` and `text_matrix` and their types at the root of `loremaster-runtime`: use `loremaster_workbench`. `Game` is `#[doc(hidden)]`; hosts use `Session`. `Session::game()` is gone.
- The terminal player plays through `Session`. A death ending shows the death prompt: type `undo` or `restart`.
- **Breaking (JS API):** the wasm `Engine` class is gone. The web engine exports two classes that mirror the Rust split (ADR 0003): `Session` for players (`start`, `submit(input)`, `choose`, `resume`, `undo`, `undoSteps`, `setUndoDepth`, `setHostRolls`, `restart`, `snapshot`, `restore`, `save`, `load`, `status`, `scene`, `verbs`, `preview`, `talk`, `choices`; each play call returns a `Step` of effects and a status) and `Workbench` for the editor (play as whole turns with `start`, `play(input)`, `resume`, `undo`, `restart` and `author`, the session's queries, `carryOver`, and the authoring views). `input`, `act`, `leave`, `reset` and `tokens` are gone: use `play` with an `Input` (`{ type: "text" | "command" | "choice" | "tick", value }`), `restart`, and the free function `markupTokens`. `load(save)` (was `restore(save)`) returns `{ story_changed, from_version, dropped }`. The TS wrapper in `web/src/lib/engine/index.ts` calls only these two classes, and the player uses only the workbench.
- The web player shows what a paused rule or the death prompt waits for (a choice, a roll, an action, a walk) with its answers, and answers with `resume`. Undo is in the turn menu and the command palette.
- **Breaking (library):** `Game` and `Restored` are no longer public in `loremaster-runtime`; use `Session` (`Session::load` returns `(Session, Loaded)`). The runtime tests play through `Session` and the hidden `authoring` primitives.
- `Session::status()` tells what the session waits for now. `Workbench` has `resume`, `undo` and `restart` as whole turns with the rule log, and `dialogues`.
- `carried(x)` is also true for a thing in a carried container.
- The ZIL importer writes containers, surfaces and local-global scenery, and reads `machines/` and `timers/` for the flags that they use.
