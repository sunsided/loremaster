## [0.4.0] - 2026-11-09

### Upgrading from 0.3

Stories and saves from 0.3 load unchanged. Library code: `Workbench::reload` returns `Result<Reloaded, ReloadError>` instead of `()`; handle or ignore the result.

### Added

- `--watch` on the terminal host example: edit the YAML of a running story and the game carries on in the new version, keeping the player's place. A broken change prints its diagnostics and play continues on the last good version. The edit shows after the next command.
- `Session::reload(world, walkthroughs)`: continue a running game in a changed world, for live reload in native dev builds. The room, values, things, timers, fired rules, talk and agendas carry over, and the hint book is built again from the walkthroughs. It returns `Reloaded { dropped }`, what the new world no longer has, in the keys of `Loaded::dropped` (`fact:…`, `thing:…`, `room:…`, `rule:…`, `once:…`, …). A session from `Session::for_host` refuses a world with another interface with `ReloadError::InterfaceChanged` and stays unchanged: the host must be rebuilt. `Workbench::reload` and `authoring::carry_over` use the same code. On a reload the hint progress follows the new walkthroughs: steps they no longer have are forgotten (done ones are listed as `step:…`), and a shorter ladder does not show its command unasked. Without walkthroughs there is no ladder to compare against, and the hint progress stays as it is.
- `LiveStory` in `loremaster-dsl` (native only): live reload in dev builds. `poll()` re-reads the YAML folders of a `Loremaster` builder and, when a file changed, builds a new world with the Rust-pack behaviors and the host's `behaviors(..)` registered. It returns `Rebuilt { world, walkthroughs, warnings }`, or the diagnostics once per broken change; `None` when nothing changed.
- **Breaking (library):** `Workbench::reload` returns `Result<Reloaded, ReloadError>` instead of `()`, so a refused reload and the dropped list reach the caller.

### Fixed

- A reload in the editor moves a thing `in` or `on` a thing that is no longer a container or supporter back to its start location, as loading a save does; it also trims the dialogue nodes for `go: back` that the dialogue no longer has.

## [0.3.0] - 2026-11-09

### Upgrading from 0.2

Saves from 0.2 load unchanged. Stories from 0.2 load unchanged, with two exceptions that `loremaster check` now reports as errors: an id `combat_hit`, `combat_round` or `combat_end` (rename it), and a host event read like a thing, such as `present(killed)`, `seen_by(killed)` or `killed.name` (read its arguments, `killed.boss`, instead; #208). Library code that builds these types with a struct literal, or matches them exhaustively, needs the changes:

- model: `Rule` (`once` is now `Once`, new `free`), `Thing` and `NameStage` (`head`), `Story` (`reload_rolls`), `Effect` (new variant `EndCombat`); project: `StoryHeader` (`reload_rolls`)
- runtime: `Turn` (`moves`), `Block` (`cause`), `Run` (`emphasis`), `ThingInfo` (`head`, `aliases`, `location`), `Scene` (`minutes`), `State` (`once_groups`), `CombatState` (`by`, `target`, `rolls`), `NoReturn` (`only_ahead`), `AwaitRequest::Roll` (`who`, `against`; match it with `..`)
- `authoring::replay_step` returns `Option<(Turn, Vec<String>)>`; `loremaster_lang::Scope` has `events`, and `Scope::things` no longer has the host events

### Added

- Once-groups (#225): `once: <key>` on a rule puts it in a once-group; all rules with the same key fire at most once in total, and the first that fires closes the group. `once: true` and `once: false` stay as they were. The save keeps the closed groups in the new state field `once_groups` (old saves load with none), and the explorer counts them in its state key. `loremaster check` warns about a group with only one rule. `world!` writes `once(greet)`, the builder `.once_group("greet")`.
- **Breaking (library):** `Rule::once` is now `Once` (`Once::Rule(bool)` or `Once::Group(key)`) instead of `bool`, and `State` has the new field `once_groups`; code that builds them with a struct literal needs them.
- Sound lines (#222): a sound line, such as an NPC's "clank, clank", is a `play_sound` of an asset with a `caption`, not a `say` with a text prefix. `loremaster play` and the terminal host now print the caption of each sound; before, `loremaster play` dropped sounds and the terminal host reported an unknown effect. `docs/writing-stories.md` and the terminal host's README say so for authors and hosts.
- Combat events (#230): a combat sends the rule events `combat_hit` (before a hit counts; `combat_hit.enemy`, `.target`, `.damage`, `.round`), `combat_round` (at the end of a round; `combat_round.enemy`, `.round`, `.won`) and `combat_end` (`combat_end.enemy`, `.outcome`: `win`, `loss`, `escape` or `ended`). Rules hear them with `on: { event: combat_hit }`, as host events, so they work in the web player, the walkthroughs and the explorer, and with host rolls. A rule on `combat_hit` changes the damage of the hit with `set: { combat_hit.damage: 0 }`. The new effect `end_combat: <room>` ends the combat in any room; `world!` has `end_combat road;` and the builder `Effects::end_combat`. A combat sets the arguments only when a rule listens for the event, so other stories and their saves do not change. When a `combat_hit` rule ends the combat, the other hits of that round still count. `loremaster check` knows the events and their arguments; it warns about a rule on them in a story without `combat` and about `end_combat` outside a rule on `combat_hit` or `combat_round`, and rejects `goto`, `await` and `combat` in such rules and `end_combat` in timers, agendas and dialogues.
- **Breaking (stories):** `combat_hit`, `combat_round` and `combat_end` are reserved names: a room, thing, variable or host event with such an id is an error.
- **Breaking (library):** `Effect` has the new variant `EndCombat`.
- A head noun for things (#234): `head: bottle` on a thing or a name stage names the main word of the name for hosts, and `ThingInfo` has `head`: the declared head of the current name, else its last word. `loremaster check` reports a `head` that is not a word of the name (or stage text) or a word of one of its aliases. Authors set `head` where the last word is wrong, as in "bottle of wine". A blank `head` counts as none. The builder has `ThingBuilder::head`; in `world!` it waits, and the YAML-to-Rust export keeps it as a hand-written field.
- **Breaking (library):** `Thing`, `NameStage` and `ThingInfo` have the new field `head`; code that builds them with a struct literal needs it.
- `Session::verbs_for(id)` (#235): the verbs that apply to a thing in scope now, sorted by id. A verb applies when a rule (`verb` or `check`) for the player's commands names the thing as its direct or indirect object, when the thing has a frame for it, or when the default of a standard verb does something for the thing in this state: `examine` always, `take` for a portable thing not held, not in a closed container and with free hands, `drop` and `put` for a carried thing, `put` for a container or supporter, `open` while closed and unlocked, `close` while open, `unlock` or `lock` for a lock whose key the player carries and for a key whose lock is in scope, `turn_on` or `turn_off` for a thing with `lit`, `use` for those, `talk` for a dialogue partner with a start node that applies, and `search` when the thing hides something. Rule conditions are not checked. Protocol mode has `session/verbs_for { id }`, the WASM binding `verbsFor(id)` on `Session` and `Workbench`.
- A typed effect for an actor's walk (#224): each walk of an agenda step gives `Effect::Moved { moved: MoveDetail }` with the actor's id and current name and the rooms `from` (None when the actor was in no room) and `to`, in the same step as the `move` notice, so a host does not parse `<actor> -> <room>`. The web types have `moved`; the terminal player ignores it.
- **Breaking (library):** `Turn` has the new field `moves`; code that builds it with a struct literal needs it. `Effect` is `#[non_exhaustive]`, so the new variant breaks no match.
- The ending checks tell a late turn from a turn that closes endings itself (#245, #170). A `closes` that fires on the turn accepts its drop as before. A `closes` that fires only later accepts a drop silently when the state after the turn still reaches the ending once time does not count: over the explored turns of its twins, states that differ only in the clock, the timers, what the agendas have done and where their actors are (the visits count when the story reads them, and an actor's place counts when a `move` can move it). Then the turn was only late. Otherwise the drop stays accepted, but `NoReturn` lists the endings in the new field `only_ahead`, the check reports an info at the turn's own rule or step (also next to the warning of a drop with unaccepted endings; a twin group that the budget cut proves nothing), and the explorer view shows a note. So a step that drops an ending without its own `closes` (Marsh taking the pages in the Lock-Keeper demo) is no longer hidden behind the coroner at three, and the demo and CI do not fail on it.
- **Breaking (library):** `NoReturn` has the new field `only_ahead`; code that builds it with a struct literal needs it. With `only_ahead`, `NoReturn::rule` names the turn's own rule that changes the state before a closer ahead.
- Free rules (#223): `free: true` on a `verb` or `check` rule lets the player's command that fires it take no time: no clock, no turn count, no timers, no agendas, as for a command the game refuses. For a refusal that changes nothing ("It is already open."); default refusals still take a turn. A free command still counts as an action and an interaction (`action.*`, `.interactions`, repeats), only not as time; an `enter`, `leave` or `event` rule it sets off does not make it free. Walkthroughs and the explorer play it as the game does. `loremaster check` warns about `free` on another event. `world!` writes `free` after the event, the builder `.free()`.
- **Breaking (library):** `Rule` has the new field `free`; code that builds it with a struct literal needs it.
- Labels on host roll awaits (#231): `AwaitRequest::Roll` has `who` (as in `RollDetail::who`: the enemy's name or `You` for a combat round, `LUCK` for "Test your Luck", the stat label for `against`) and `against` (the `against` variable, for example `luck`). The web player's prompt says "Roll for GATE WARDEN 2d6", and "Your roll: 2d6" for the player's own roll. Saves and awaits without the fields still load.
- **Breaking (library):** the struct variant `AwaitRequest::Roll` has the new fields `who` and `against`; code that builds or matches it exhaustively needs them (or `..`).
- `world!` writes the wildcard verb bare (#220): `rule grope on verb(*, darkness) { .. }` and `on check(*)`, the same as `on::verb(["*", "darkness"])` in the builder. `*` goes only in the verb place.
- Each output block has a `cause` (#178): `command` for the player's input (its response, the rules it fired, the room after a move, an answer), `world` for the opening, the turn passing (`on: turn`, timers, time rules, agendas, orders) and the rules of a host event. A graphical host can draw the player's own text over the player and the rest as ambient narration.
- `Session::thing(id)` (#178): any thing of the story with its current name and its location, also outside the player's room. Like `snapshot`, it sees everything, also concealed things. Protocol mode has `session/thing { id }`, the WASM binding `thing(id)`.
- **Breaking (library):** `Block` has the new field `cause`, and `ThingInfo` has the new field `location`; code that builds them with a struct literal needs them.
- Emphasis as a run attribute (#194): `*Kestrel*` in story text is now a run with `emphasis: true` and the text `Kestrel`, without the stars, also when a thing link splits it. A pair of stars with a space just inside (`2 * 3 * 4`) stays text, and so does `**`. `Block::plain_text` puts the stars back, so transcripts and walkthrough checks do not change. `loremaster play` and the web player show emphasis from the attribute; `Choice::text` keeps its stars.
- The story bundle (#194): `Bundle` (format `loremaster-bundle`, version 1) holds a story, its walkthroughs and the loremaster version that wrote it. `Bundle::from_json` refuses another format, a missing version and a newer version. `Bundle::session` compiles the story and sets the hint ladder; a story with Rust behaviors starts with `Bundle::session_with`, which registers them, and a behavior left unregistered is a `BundleError`. A host writes it in its `build.rs` in place of its own `(Story, walkthroughs)` JSON.
- **Breaking (library):** `Run` has the new field `emphasis`; code that builds it with a struct literal needs it. A host that reads `Run::text` gets emphasized text without its stars.
- Host queries from the lock-keeper UI (#194): `Session::fact(name)` reads one variable, property or machine state without a copy of the state (protocol `session/fact { name }`, WASM `fact(name)` on `Session` and `Workbench`); `ThingInfo` has `aliases` (its aliases and the names of earlier name stages; the Atlas fills them too); `Scene` has `minutes`, the clock as a number next to `time`. The terminal host's README says how a host reads links, nouns and `VerbInfo::slots`.
- **Breaking (library):** `ThingInfo` has the new field `aliases`, and `Scene` the new field `minutes`; code that builds them with a struct literal needs them.
- `reload_rolls` in story.yaml (#189): `same` (strict, the default) keeps the next roll after a load, `fresh` (forgiving) rolls anew. `Session::reseed(entropy)` (WASM `reseed`) mixes the host's randomness into the RNG after `load`, `from_save` or `restore`, and changes nothing for `same`. The host passes a fresh, unpredictable value on each load. The web engine wrapper and the terminal host call it after each load. `loremaster new` writes `reload_rolls: same` into story.yaml, the builder has `fresh_rolls()` and `world!` the header key `reload_rolls: fresh`. The setting is not part of the save's story fingerprint, so switching it does not make old saves look like saves of a changed story.
- **Breaking (library):** `Story` and `StoryHeader` have the new field `reload_rolls`.
- The wildcard verb in rule events (#192): `on: { verb: ["*", darkness] }` matches any verb on the darkness, also for `check`. An exact-verb rule that fires in the same scope and phase holds the `*` rule back, so only its text shows. `loremaster check` accepts `*` in rules and refuses it in an agenda step's `do` and as the id of a story verb, and the explorer tries each verb that fits the objects. `CommandPattern::any_verb` and `ANY_VERB` are in `loremaster-model`. `world!` syntax waits for #220.
- `ask <person> about <topic>` (#169): the parser fills the `topic` slot of the Command record with the words after `about`, without articles, and preview stops at `about`. A rule matches it with `on: { verb: ask, direct: bert, topic: lantern }`, and the explorer tries the topics that rules name. `loremaster check` reports a `topic:` that the parser never gives (`the lantern` for `lantern`); `topic_words` and `ARTICLES` in `loremaster-model` are the parser's form. `ask` and `show` (`show <thing> to <person>`, two objects) are custom verbs; `docs/writing-stories.md` has both. "He ran" and Hester's alibi in the Lock-Keeper demo came with #216.
- Combat (#190): in an all-at-once combat with more than one living enemy, the player selects the target ("Attack HOUND", `attack.hound`; `attack` is still the first living enemy). The enemy properties `deals` and `takes` are special rules of one enemy: the STAMINA a hit costs the player or the enemy, instead of 2; Luck shifts them as it shifts the 2, and `loremaster check` rejects a value that is not a number. With `set_host_rolls(true)`, the host answers the dice of a combat as `roll` awaits: one per enemy that fights, then the player, and one for "Test your Luck". A save while a round waits for its rolls keeps the totals so far.
- **Breaking (library):** `CombatState` has the new fields `by`, `target` and `rolls`. Saves stay compatible: the fields default to empty.
- `await`, `combat` and `stats` in `world!` and the builder (#191), so a story with rolls or fights does not need YAML. `world!` has the effects `await roll "2d6" into r against luck;`, `await choice [..] into ..;`, `await walk_to ..;`, `await action .. { .. } results [..] into ..;` and `combat [warden] win yard loss fallen escape road together;` (`escape` and `together` are optional), and `stats { stamina "STAMINA" short "ST" max stamina_initial, .. }` in the story header. The builder has `Effects::awaits`, `Effects::combat` and `StoryBuilder::stat`, `stat_short` and `stat_max`. `AwaitSpec` now derives `Default`.
- `Workbench::replay_step` (WASM `replayStep`) plays one step of a path from the state explorer, as a whole turn, or gives `None` when the game has no such step now. It reads each step as the explorer wrote it, with the rolls of a combat round as the walk forced them, and with host rolls and host walks off for the step, as in the walk. After the end of the story it gives `None`. Two answers with one text in a talk or a paused rule now have different labels in the explorer's paths (`say Yes.`, `say Yes. (2)`), so a path replays the answer it took.

### Changed

- The Lock-Keeper demo has "He ran" and Hester's alibi (#216). `show notes to marsh` shows Marsh the case notebook; with two kinds of proof in it he makes for the door, and the game ends in the new ending "He ran" (rank 3, between "charged" and "accidental death"; the ranks of `accident`, `released` and `wrong_man` move down by one) unless the next command is `stop marsh`, which holds him in the parlour for the rest of the night. Hester's trust is one fact, `hester.trusts`: a kind word in the kitchen before eleven sets it, she tells the truth and stays in the kitchen. Without it, a player on the barge at midnight sees her with Crane. Her alibi clears Crane and proves the opportunity. Four new walkthroughs (`ran`, `stopped`, `trust`, `follow`) with transcripts in `expected/`. The night has 72,148 states instead of 39,047, and `demo_endings_are_reachable` raises its budget to 80,000; the ending checks stay proven, with no warning.
- The two-robot demo has its water clock: the timer `water` floods the station after eight turns, and its rule `river_wins` names `closes: [drained]`. The explorer needs more than the default budget for it now (#210).
- The state explorer tells states apart only by the `once` rules that fired, not by every rule that ever fired: the game reads `fired` only to keep a `once` rule from firing again, so the results stay exact. A rule that only says a text no longer splits states. The id of the ending is in the key now, so two endings reached from one state stay two (before, the fired rules kept them apart). The explore output of the examples changes: lighthouse has 119 states instead of 287, and the Lock-Keeper demo 38,885 instead of about 60,000. The demo keeps its 15-minute turns; time bands would not be exact, so the ending checks would miss the drops from a turn that comes too late (#239). (#168)
- Host event arguments are their own namespace in conditions and text (#208). Before, an event read like a thing, so `present(killed)`, `killed.name` or `seen_by(killed)` passed the check. Now they are errors, and `killed.bos` says the event has no such argument, with a hint to `killed.boss`. An event still cannot have the id of a thing, a variable, a room or a built-in path: `killed.level` would still read as a thing's property or a room's `visits`, and the fact keys would clash.
- **Breaking (library):** `loremaster_lang::Scope` has the new field `events`, and `Scope::things` no longer has the host events.
- An order step is the player's action, decided in #209: the rules for the player fire for it (with `bilge.active` true), and it counts in `action.*`, `.interactions`, `.talked` and `once`, as a step after a switch does. `docs/writing-stories.md` says so. A rule with `actor: bilge` for a playable actor now gets an error that says to declare `active` in its `props` and test `bilge.active` instead; before, the error said to give it an agenda, which a playable actor cannot have.

### Fixed

- The ending checks' timeless twins are exact in three more places (#262). An agenda actor's place now counts in the timeless key when something besides its agenda can move it: a `move` effect, the player carrying it (`portable`), its orders (`playable`), or any behavior (a `call` effect or a registered behavior). Before, a player who carried such an actor off could drop an ending without any report. The visits count when a compiled condition, markup or first-visit text reads them, no longer when prose or a note says "visited". A twin group with a timeless path into a group that the walk did not finish is inconclusive, as a group with such a state already was. The Lock-Keeper demo keeps its 21 infos and the salt tower its 2, with no warnings.
- Answer labels in the explorer's paths no longer collide when an answer text itself ends in a suffix: the choices `Yes.`, `Yes.` and `Yes. (2)` now give `say Yes.`, `say Yes. (3)` and `say Yes. (2)`, so a path replays the answer it took (#247). `authoring::replay_step` now returns the errors of the step's forced combat rolls next to the turn, for example a total that the replay did not take; before, they were dropped. It clears the forced rolls first, so none leak into a later step. `Workbench::replay_step` (WASM `replayStep`) still returns only the turn. **Breaking (library):** `authoring::replay_step` returns `Option<(Turn, Vec<String>)>`.
- A thing whose `names:` stages all have a `when` that does not hold now has its `name`. Before, it showed the text of the first stage (#178).
- `Command::verb("go", vec!["up".into()])` now moves the player like `Command::Go`, also for the active actor, when the object is a compass word or an exit of the room. Before, it ran as a verb that did nothing. `go` with a thing, and a story's own verb `go`, stay verbs (#178).
- The room that `undo` and `restore` show now has its thing links, like every other room description (#194).
- A cancelled job no longer shows as failed, with the error of the killed agent, before it shows as cancelled (#185). A loom test (`task test:loom`) checks all orders of cancel and the end of a job.
- A condition with a character other than a letter outside the ASCII range, such as `€` or an emoji, made `loremaster check`, the editor and the engine loop for ever; now it is an error at that character (#186).
- An `add` past the range of a whole number no longer stops the game (a debug build) or wraps round; the value stays at the largest or smallest number (#186).
- The "Replay this path" buttons of the explorer in the web editor play `say`, `answer` and `leave` steps, and steps with a preposition or a topic, through `Workbench::replay_step`. Before, a path through a talk or a paused rule stopped working at that step (#163).
- The state explorer tells states apart by the turns left of each timer. Before, an ending that a timer triggers was never reached, and the ending checks missed the points of no return that a timer makes (#210).

## [0.2.0] - 2026-11-09

### Added

- Scenes with hotspots and walks for stage hosts (P6-02, #96). A variant of a room's `illustration` has `regions`: `{ thing: iron_gate, rect: [31, 33, 38, 67] }` or `{ exit: north, rect: [..] }`, in percent of the image. `Session::media()` has the field `regions` with the hotspots the player can see now, each with its name. `Session::set_host_walks(true)` (WASM `setHostWalks`) makes a command on a thing in the room, or a move, first wait for `walk_to` with that `thing` or `exit`; `arrived` runs the command and `refused` drops it. Without it, nothing changes. `loremaster check` reports regions that point to nothing. The web player shows the hotspots as buttons over the illustration, and the gatehouse example has them.
- **Breaking (library):** `AwaitRequest::WalkTo` has the new fields `thing` and `exit` (match it with `WalkTo { room, .. }`), `Awaiting` has the new field `command`, and `MediaVariant` has the new field `regions`. `Command` now derives `Hash`.
- Editor overrides of Rust parts (DSL step L6, DS-11 to DS-15, #99). Each entity from Rust has a content hash of its model value in its `Origin::Rust`. A YAML file with an `override:` block replaces a Rust part and keeps its base (file, line, entity, hash, commit, and the value for the diff). `assemble` compares: Rust unchanged is a warning, Rust changed is an error with a three-way diff, Rust equal to the override is an info. `loremaster codegen <dir>` prints overrides as `world!` snippets, `loremaster export-pack` writes Rust packs to `packs/*.yaml` for the generic editor (`Pack::to_yaml`; it writes them atomically and removes stale ones; only the top level of `packs/` is read, any other file there is an error, and a leftover `packs/*.json` says to export again). Two dialogues or two verbs with one id are an error, as for the other kinds, and `world_test!` with `Loremaster::assert_world` and `strict` is the whole-world test. The editor shows Rust parts read-only with their source line in Atlas › Rust and can eject or override them. `examples/rust-overrides` is the reference example.
- **Breaking (library):** `Origin::Rust` has the new field `hash`, `Severity` has the new variant `Info`, `Pack` has the new fields `overrides` and `commit`, and `Project` has the new field `rust_parts`.
- The host contract (P6-03, #97). `interface:` in story.yaml (or `interface { .. }` in `world!`) declares every custom action (name, typed arguments, results) and every host event (name, typed arguments, optional precondition). With the section, `loremaster check` fails on an undeclared action or event, a wrong argument type and a missing branch for a declared result. `Session::host_event` reports an event, `Session::for_host` and `Session::check_interface` refuse a host built for another interface hash, and name the added, removed and changed entries. A walkthrough reports an event with `{ event: killed, args: { .. } }` and gives only declared results. The new crate `loremaster-build` (for `build.rs`) and `world!` generate the Rust types; `loremaster interface <dir> [--rust|--ts|--json-schema]` writes them for other hosts. The names of the interface are plain names, and the check reports two that make one Rust name. Stories without the section work as before.
- Protocol mode (US-65): `loremaster protocol <dir>` plays a story as a JSON-RPC server on stdio, one message per line, with the Session API as methods. It lives next to the MCP server in `loremaster-mcp` and leaves the MCP tools alone.
- **Breaking (library):** `Story` and `StoryHeader` have the new field `interface`, and `StepPlan` has the new fields `event` and `args`; code that builds them with a struct literal needs them.
- Media and audio slots with captions (P6-01, #95). A room, thing or machine state has `media:` (illustration, portrait, music, ambience) with variants by condition. Assets are in `assets/` with `file`, `caption`, `licence`. `play_sound` is a one-shot rule effect, and a walkthrough checks it with `sound:`. `Session::media()` derives the slots from the state, so they are not saved. `loremaster check` reports missing and unused assets, missing files, licences and captions. The web player shows images, plays audio after the first input, and has captions, three volumes and a mute key (Alt+M); the sound is off by default. The new example `gatehouse` is the fixture.
- **Breaking (library):** `Room`, `Thing`, `StateDef::Described`, `Story`, `Pack` and `Expect` have new fields, `Effect` (model) has the new variant `PlaySound`, and `Turn` has the new field `sounds`. `session::Effect` has the new variant `Sound` (it is `non_exhaustive`).
- Episodes (TX-12, US-13, dramaturge#81): `export:` and `import:` in story.yaml list the facts, relations (`thing.axis`) and memories (`thing.key`) that one story of a series hands to the next. `loremaster check` examines both lists. `Session::episode()` writes an `Episode` (format `loremaster-episode`, version 1, the story id), and `Session::from_episode` starts a new game of the next story with what it imports; the `Imported` report lists what it took, what the story does not import and what does not fit. An imported memory declares its key for `remembers()`.

### Changed

- The `when` of a host event sees the reported arguments; a refused event keeps the values before. An event cannot have the id of a room, a keyword or a built-in path (`time`, `action`, `timer`). An event step of a walkthrough is done when the session accepts a report of its event with its `args` and its `facts` hold; a later step that `needs` it can then open in the hint ladder.
- loremaster depends on dramaturge 0.3 from crates.io (`"0.3"`, now 0.3.1; P3-14). dramaturge 0.3 rejects text keys that would share progress (empty, digits only, containing `/`, or repeated) when it loads a dialogue or a pool; no example uses such a key.
- **Breaking:** save version 3 (ADR 0001). Text progress uses dramaturge's keys: `room:shore/2` instead of `room:shore#2`, and the fragment's `id` in place of its index when it has one. The save field `sticky` of a fragment's progress is `pick` now (`sticky` still loads), and the step from version 2 renames old keys; a fragment with an `id` starts its progress over. `shuffle` never shows the variant it showed last; `first_visit` on an examined thing, the intro and a frame means the first time the text shows, and on a presence text the first visit of the room, as on a room. The explorer finds 4 instead of 3 texts of the Lighthouse shore (its `shuffle` fragment); no walkthrough or test transcript changed.
- The explorer counts a walk that the depth limit (40 commands) stopped as `truncated`, as one that the state budget stopped. `stuck` counts only proven dead ends: a state whose future the walk did not finish is not one.
- Dialogues use more of dramaturge 0.3: `add` lowers to `Outcome::AddFact` (a missing value counts as 0 as before; the sum now saturates at the `i64` limits instead of overflowing), `remembers()` queries the memory id (memories no longer carry the key as a tag), the checker filters validator issues by kind and skips cycles through the validator options, and the player's key comes from `SymbolTable::PLAYER_KEY`. Saves stay compatible.
- **Breaking (library):** `loremaster_lang::ADD_KEY` and `loremaster_lang::memory_tag` are removed.
- Dialogues run through more of dramaturge 0.3: the start nodes are the entry nodes of the graph, and a talk starts at the first one whose `when` holds through dramaturge's `select_entry`. The checker no longer needs to drop the "unreachable" warnings of start nodes. A `then` list is a typed host outcome (`Outcome::Host`) in the graph, not a custom outcome with an index into a side list, and each line is typed host text (`DialogText::Host`) with its compiled markup, not a side table. A node is entered through dramaturge's `enter_node`, and `go` and `go: back` move a dramaturge `DialogCursor`. Saves keep the talk as node keys, as before.
- A `go` to a node whose `when` does not hold ends the talk. Before, the talk entered the node anyway. A `when` on a node that is not a start node was not documented. `go: back` returns to the node before without a check, as before: that node was entered already, and its outcomes do not apply again.
- **Breaking (library):** `CompiledDialogue` is now the lowered graph itself, a `DialogueGraph<Vec<Effect>, CompiledLine>`. Its fields `starts`, `effects`, `node_say` and `option_say` and `loremaster_lang::THEN_KEY` are removed; use `entry_nodes`, `Outcome::Host` and `DialogText::Host`.
- **Breaking:** a variable, machine, room or thing whose id is a built-in name of conditions (`here`, `turns`, `level`, `first_visit`, `time`, `action`, `timer`, `true`, `false`, `and`, `or`, `not`, the functions `in`, `carried`, `present`, `visited`, `visits`, `chance`, `remembers`, and the planned `seen_by`) is a check error at its declaration, and so is a variable or machine with the name of a clock phase. Before, it loaded, and its conditions silently read the built-in, or the variable instead of the phase. `loremaster_lang::RESERVED_NAMES` is the one list, and `loremaster_lang::reserved` tells a keyword, a derived value and a function apart for the message; the ZIL importer uses it too and adds `_zil` to such names and to the phase names of the default clock.
- **Breaking:** the loader rejects an unknown field in every entity file (rooms, things, rules, dialogues with their nodes and options, timers, verbs, machines, story.yaml and walkthrough steps and `expect`), an unknown folder and a YAML file other than story.yaml at the top, with the nearest known name: ``unknown field `descripton`: did you mean `description`?``. Before, only endings, threads and story.yaml rejected unknown fields, and an unknown folder loaded as nothing. A fragment with an unknown field names the field instead of "did not match any variant". The folders `agendas/` and `texts/` of the golden slice are skipped with a warning. `loremaster_project::FOLDERS` lists the folders, and `Pack::warnings` holds the warnings of a pack.
- **Breaking (library):** `Cx` is a narrow, stable view for behaviors (XP-1, XP-7). `Cx::state()` and `Cx::world()` are gone; use the new `turns`, `minutes`, `visited` and `room_has_tag`, or the read-only escape hatch `Cx::unstable()`. Random numbers come only from `Cx::roll`.
- **Breaking:** the loader reads `agendas/` (D6) instead of skipping it with a warning. `texts/` loads since P4-01 (#78), so no folder is skipped any more.
- The turn log of a talk shows what a dialogue really changed, in the order of the changes, with the new values. Removed facts and forgotten memories get a line; a relation change of 0 and a fact outside the world scope do not.
- The room matrix and the text matrix try the player's relations to things (`blackbeard.trust`) as a dimension.
- One diagnostic form (XP-6): `Diagnostic` and `Severity` live in `loremaster-model` (`loremaster-project` re-exports them) and can be deserialized. A compile error becomes a `Diagnostic` with `Diagnostic::from(&error)`, and `Project::locate` gives it the file of its entity. The CLI, the web engine and the AI tools report compile errors with their file now.
- **Breaking (library):** `Project::origins` maps to the `Origin` enum (`Yaml { path }`, `Rust { file, line, column, pack }`, non-exhaustive) instead of a path string. `Origin::file()` gives the path.
- `Game::save` and `Game::load_save` read and write save games. The web engine's `save()` and `restore()` and the AI tools `save` and `session_start` use the envelope; `restore()` returns the dropped ids.
- **Breaking:** the `end` effect names an ending from `endings/` (`end: beacon_lit`) instead of a text. Move the text into `endings/<id>.yaml` with a `kind` and a `title`. The lighthouse and the tower examples show it.
- **Breaking (library):** the authoring views moved out of `Game` into `loremaster-workbench`. `Game::atlas`, `map`, `rules`, `machines`, `symbols`, `try_markup`, `try_condition`, `try_markup_situation` (now `Workbench::try_markup_in`), `preview_situation`, `describe_preview` (now `Workbench::describe`), `assembly`, `room_parts`, `last_frame`, `talk_view`, `inspect_thing`, `inspect_exit`, `vars`, `phases`, `author` and `carry_over` (now `Workbench::reload`) are gone from the public API, and so are the free functions `explore`, `room_matrix` and `text_matrix` and their types at the root of `loremaster-runtime`: use `loremaster_workbench`. `Game` is `#[doc(hidden)]`; hosts use `Session`. `Session::game()` is gone.
- The terminal player plays through `Session`. A death ending shows the death prompt: type `undo` or `restart`.
- **Breaking (JS API):** the wasm `Engine` class is gone. The web engine exports two classes that mirror the Rust split (ADR 0003): `Session` for players (`start`, `submit(input)`, `choose`, `resume`, `undo`, `undoSteps`, `setUndoDepth`, `setHostRolls`, `restart`, `snapshot`, `restore`, `save`, `load`, `status`, `scene`, `verbs`, `preview`, `talk`, `choices`; each play call returns a `Step` of effects and a status) and `Workbench` for the editor (play as whole turns with `start`, `play(input)`, `resume`, `undo`, `restart` and `author`, the session's queries, `carryOver`, and the authoring views). `input`, `act`, `leave`, `reset` and `tokens` are gone: use `play` with an `Input` (`{ type: "text" | "command" | "choice" | "tick", value }`), `restart`, and the free function `markupTokens`. `load(save)` (was `restore(save)`) returns `{ story_changed, from_version, dropped }`. The TS wrapper in `web/src/lib/engine/index.ts` calls only these two classes, and the player uses only the workbench.
- The web player shows what a paused rule or the death prompt waits for (a choice, a roll, an action, a walk) with its answers, and answers with `resume`. Undo is in the turn menu and the command palette.
- **Breaking (library):** `Game` and `Restored` are no longer public in `loremaster-runtime`; use `Session` (`Session::load` returns `(Session, Loaded)`). The runtime tests play through `Session` and the hidden `authoring` primitives.
- `Session::status()` tells what the session waits for now. `Workbench` has `resume`, `undo` and `restart` as whole turns with the rule log, and `dialogues`.
- `carried(x)` is also true for a thing in a carried container.
- The ZIL importer writes containers, surfaces and local-global scenery, and reads `machines/` and `timers/` for the flags that they use.

### Removed

- **Breaking (library):** `Awaiting` no longer has the field `locals`. It was never filled; a rule keeps values between await and resume in story variables (`into:`). Saves do not change, because the empty field was never written.

## [0.1.0] - 2026-10-31

### Added

- The first release on crates.io: `loremaster` (the command), `loremaster-model`, `loremaster-lang`, `loremaster-project`, `loremaster-runtime`, `loremaster-tools` and `loremaster-mcp`.
- `cargo install loremaster` gives the binary with the web editor in it.

### Notes

- The public API of `loremaster-lang` and `loremaster-runtime` uses types from dramaturge 0.2. A new major version of dramaturge thus can also be a breaking change of loremaster.
